---
title: Market-Maker Fast Path
description: "Build and sign orders locally — zero HTTP on the hot path."
---

Normal SDK calls make one round-trip to the tx-builder API per order. For market makers, `local_intents()` removes it: the `LocalIntentBuilder` mirrors the on-chain EIP-712 schemas (proven byte-for-byte by the golden-vector test suite), so the hot path becomes **local build → local sign → relayer POST**.

```python
from avantis_trader_sdk import AsyncAvantis
from avantis_trader_sdk.types import AggregatorOrderType

async with AsyncAvantis() as client:
    builder = await client.local_intents()      # one-time meta bootstrap
    engine = client.engine
    eth = await client.markets.pair("ETH/USD")

    async def on_price(update) -> None:
        payload = builder.open_trade(           # microseconds, no I/O
            trader=client.trade.trader,
            pair_index=eth.index,
            is_long=True,
            collateral_usdc=100,
            leverage=10,
            open_price=update.price,
            slippage_percent=0.3,
        )
        receipt = await engine.submit_intent_batch(
            payload, AggregatorOrderType.MARKET_OPEN, wait=False
        )
        print("queued:", receipt.request_id)

    stream = client.lazer_price_stream([eth.lazer_feed.feed_id])
    await stream.run(on_price)
```

## Builder surface

| Method | Intent |
| --- | --- |
| `builder.open_trade(...)` | Market open |
| `builder.open_trade_coin(...)` | Market open sized in coin units |
| `builder.close_trade(...)` | Market close |
| `builder.close_trade_coin(...)` | Market close sized in coin units |
| `builder.increase_position(...)` | Increase position size |
| `builder.increase_position_coin(...)` | Increase sized in coin units |
| `builder.update_tp_sl(...)` | TP/SL update |
| `builder.partial_tp_sl(...)` | Partial TP/SL trigger (stored off-chain — see below) |
| `builder.twap_open(...)` / `builder.twap_close(...)` | TWAP open / close |
| `builder.delegate_req(...)` | Delegate registration |
| `builder.register_code(...)` / `builder.set_referral_code(...)` | Referral (referral domain; trader key only) |
| `builder.build(kind, message)` | Any of the 15 intent kinds, raw (incl. RFQ, which has no helper yet) |

Payloads are `IntentPayload` objects identical to what the tx-builder would return, and go through the same digest-verified signer.

Since the builder never touches the network, prices are always caller-supplied: coin/increase helpers take an explicit `open_price`/`wanted_price` (the tx-builder route would resolve these from the feed). Note `partial_tp_sl` only *builds* the TpSlReq — the signed order still has to be stored via the core API `/offchain-orders` (what `client.trade.partial_tp_sl` does), not submitted to the relayer.

## Settling relays

`wait=False` returns as soon as the relayer accepts the request — but a queued relay can still **fail** (reverted on-chain, or timed out inside the relayer). You own the settlement check. Off the hot path, poll by the `request_id` from the receipt:

```python
from avantis_trader_sdk.errors import RelayError, RelayTimeoutError

try:
    status = await engine.relayer.wait(receipt.request_id)  # polls until settled
    print("mined:", status.tx_hash)
except RelayTimeoutError:
    # not settled within relay_poll_timeout_s — it may still land,
    # so check positions before assuming failure
    ...
except RelayError as exc:
    # rejected by the relayer or reverted on-chain (exc.request_id)
    ...
```

For your own reconciliation loop, `engine.relayer.status(request_id)` is a single non-blocking poll returning a `RelayStatus` (`settled`, `success`, `tx_hash`, `error_message`) — this is exactly what the default `wait=True` path runs internally.

## Pair with

- `wait=False` on submission, confirming fills via the [order event stream](/data/prices-and-streams) or by polling `engine.relayer` as above.
- The Lazer SSE price stream for the freshest `open_price`.

Quote-to-order latency is then bounded only by the relayer POST.
