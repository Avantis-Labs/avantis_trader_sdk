---
title: Market-Maker Fast Path
description: "Build and sign orders locally, then submit with a single HTTP call. Zero round-trips before submission."
---

Normal SDK calls ask the tx-builder API for each order's signing payload. Market makers can skip that. `local_intents()` / `localIntents()` returns a builder that mirrors the on-chain EIP-712 schemas, proven byte for byte by the golden-vector test suite, so orders are built and signed in microseconds with no network access.

The batched-market service accepts a signed intent on its own. The hot path is therefore: build locally, sign, one POST. Nothing else happens before submission. The high-level calls such as `market_open` also attach a pre-signed EIP-7702 transaction, which lets the server pick the execution mechanism; pass calldata to `submit_intent_batch` / `submitIntentBatch` if you want that from the fast path too.

The example sizes the order in coin units, exactly 0.5 ETH, which is the usual shape for market-making flow. The fill leverage floats between the minimum and maximum. For a USDC-sized order use `open_trade` / `openTrade` with `MARKET_OPEN` instead.

<CodeGroup>

```python Python
from veranta_sdk import AsyncVeranta
from veranta_sdk.types import AggregatorOrderType

async with AsyncVeranta() as client:
    builder = await client.local_intents()       # one-time bootstrap from /v2/meta
    engine = client.engine
    eth = await client.markets.pair("ETH/USD")
    lev = eth.leverages

    async def on_price(update) -> None:
        payload = builder.open_trade_coin(       # microseconds, no network
            trader=client.trade.trader,
            pair_index=eth.index,
            is_long=True,
            collateral_usdc=100,
            coin_exposure=0.5,                   # exactly 0.5 ETH
            leverage=10,                         # reference leverage, required
            min_leverage=lev.min_leverage,
            max_leverage=lev.max_leverage,
            open_price=update.price,
            slippage_percent=0.3,
        )
        receipt = await engine.submit_intent_batch(
            payload, AggregatorOrderType.MARKET_OPEN_WITH_COIN_EXPOSURE, wait=False,
        )
        print("accepted:", receipt.tracking_id)

    stream = client.lazer_price_stream([eth.lazer_feed.feed_id])
    await stream.run(on_price)
```

```typescript TypeScript
import { AggregatorOrderType, Veranta } from "veranta-sdk";

const client = new Veranta();
const builder = await client.localIntents();     // one-time bootstrap from /v2/meta
const engine = client.engine;
const eth = await client.markets.pair("ETH/USD");
const lev = eth.leverages!;

const stream = client.lazerPriceStream([eth.lazerFeed!.feedId!]);
await stream.run(async (update) => {
  const payload = builder.openTradeCoin({        // microseconds, no network
    trader: client.trade.trader,
    pairIndex: eth.index,
    isLong: true,
    collateralUsdc: 100,
    coinExposure: 0.5,                           // exactly 0.5 ETH
    leverage: 10,                                // reference leverage, required
    minLeverage: lev.minLeverage!,
    maxLeverage: lev.maxLeverage!,
    openPrice: update.price,
    slippagePercent: 0.3,
  });
  const receipt = await engine.submitIntentBatch(
    payload, AggregatorOrderType.MARKET_OPEN_WITH_COIN_EXPOSURE, { wait: false },
  );
  console.log("accepted:", receipt.trackingId);
});
```

</CodeGroup>

## What the builder can build

| Python | TypeScript | Order |
| --- | --- | --- |
| `open_trade`, `open_trade_coin` | `openTrade`, `openTradeCoin` | Market open, USDC-sized or coin-sized |
| `close_trade`, `close_trade_coin` | `closeTrade`, `closeTradeCoin` | Market close |
| `increase_position`, `increase_position_coin` | `increasePosition`, `increasePositionCoin` | Size increase |
| `update_tp_sl` | `updateTpSl` | Full-position TP and SL |
| `partial_tp_sl` | `partialTpSl` | Partial trigger, stored off-chain |
| `twap_open`, `twap_close`, `twap_cancel` | `twapOpen`, `twapClose`, `twapCancel` | TWAP |
| `cancel_offchain_order` | `cancelOffchainOrder` | Cancel a stored partial trigger |
| `delegate_req` | `delegateReq` | Delegate registration |
| `register_code`, `set_referral_code` | `registerCode`, `setReferralCode` | Referral, wallet key only |
| `build(kind, message)` | `build(kind, message)` | Any intent kind, raw |

The builder never touches the network, so prices are always yours to supply. The payloads are identical to what the tx-builder would return and go through the same hash-verified signer.

Not everything goes to the batched-market endpoint. TP and SL intents go to the core API price-triggers endpoint, which is what `update_tp_sl` and `partial_tp_sl` do for you, and TWAP intents go to the TWAP service.

## Settling

`wait=False` returns as soon as the order is accepted, and an accepted order can still fail: a declined fill or an on-chain revert. You own the settlement check, off the hot path.

Market orders settle by tracking id:

<CodeGroup>

```python Python
from veranta_sdk.errors import RelayError

try:
    outcome = await engine.batched_market.wait(receipt.tracking_id)
    fill = outcome.terminal.data           # the trade as executed on-chain
    print("executed:", outcome.tx_hash, fill["price"], fill["t"]["leverage"])
except RelayError as exc:
    ...                                    # MarketOrderCanceled: the fill was declined, e.g. slippage
```

```typescript TypeScript
import { RelayError } from "veranta-sdk";

try {
  const outcome = await engine.batchedMarket.wait(receipt.trackingId!);
  const fill = outcome.terminal!.data;      // the trade as executed on-chain
  console.log("executed:", outcome.txHash, fill.price, fill.t.leverage);
} catch (error) {
  if (error instanceof RelayError) { /* MarketOrderCanceled: the fill was declined, e.g. slippage */ }
}
```

</CodeGroup>

The terminal event carries the full fill, so no follow-up positions query is needed. Numbers are strings in raw on-chain units; see the [fill payload](/trading/market-orders#the-fill-payload). `status(tracking_id, after_seq)` / `status(trackingId, afterSeq)` is the single non-blocking poll, and `wait` accepts an event hook too.

Passthrough actions such as limit orders and approvals settle by request id, through `engine.relayer.wait(request_id)` / `engine.relayer.wait(requestId)`. That is exactly what the default wait runs internally.

## Pair it with

- `wait=False` on submission, confirming fills through the settlement calls above or the [order event stream](/data/prices-and-streams#order-events).
- The Lazer price stream for the freshest reference price.
- A nonce pool. Intent nonces are unordered 256-bit values, so many orders can be in flight at once.
