## USDC approval for trading

Trading collateral is pulled from your wallet, so USDC must be approved to the trading contract once.

<CodeGroup>

```python Python
await client.account.approve_usdc()          # unlimited, to TradingStorage
await client.account.approve_usdc(5000)      # or a fixed amount

info = await client.account.allowance()      # balance and allowance, raw and human
```

```typescript TypeScript
await client.account.approveUsdc();          // unlimited, to TradingStorage
await client.account.approveUsdc(5000);      // or a fixed amount

const info = await client.account.allowance(); // balance and allowance, raw and human
```

</CodeGroup>

<Warning>
Approvals must come from your wallet key. They cannot go through an API key. If you onboarded with the [Veranta API Key Generator](https://delegate.veranta.xyz/), USDC was approved in the same flow and you can skip this.
</Warning>

In a React app, `useApproveUsdc()` approves from the connected wallet, gaslessly through a permit when the wallet supports it. See [React hooks](/frontend/react#usdc-approvals-from-the-browser).

## Builder-fee approval

Trading through an app that charges [builder fees](/builders/builder-codes) needs a second allowance, to the BuilderCode registry. The registry is the only contract that can pull the fees. Never approve the app's own wallet or your API key.

<CodeGroup>

```python Python
await client.account.approve_builder_fees()        # unlimited, to the registry
await client.account.approve_builder_fees(100)     # or a fixed amount
info = await client.account.builder_fee_allowance()
```

```typescript TypeScript
await client.account.approveBuilderFees();         // unlimited, to the registry
await client.account.approveBuilderFees(100);      // or a fixed amount
const info = await client.account.builderFeeAllowance();
```

</CodeGroup>

Allowances go down as fees are charged, even unlimited ones, so long-running integrations should watch the allowance and re-approve when it runs low.

## LP vault approval

The vault pulls from an allowance on the tranche contract, not the trading contract:

<CodeGroup>

```python Python
meta = await client.meta()
await client.account.approve_usdc(1000, spender=meta["addresses"]["tranche"])
```

```typescript TypeScript
const meta = await client.meta();
await client.account.approveUsdc(1000, { spender: meta.addresses.tranche as `0x${string}` });
```

</CodeGroup>

See [LP vault](/more/lp-vault).

## Claims

Both claims are caller-scoped: the signing key must be the account that earned them.

<CodeGroup>

```python Python
await client.account.claim_rebate()            # referral rebates, as the referrer
await client.account.claim_keeper_rewards()    # keeper rewards
```

```typescript TypeScript
await client.account.claimRebate();            // referral rebates, as the referrer
await client.account.claimKeeperRewards();     // keeper rewards
```

</CodeGroup>
