## Fetch positions

<CodeGroup>

```python Python
data = await client.account.positions()       # UserData

for pos in data.positions:
    print(pos.side, float(pos.collateral), "USDC at", float(pos.open_price),
          "liquidation at", float(pos.liquidation_price))

for order in data.limit_orders:
    print(order.side, float(order.collateral), "at", float(order.price))
```

```typescript TypeScript
import {
  limitOrderCollateral, limitOrderPrice, limitOrderSide,
  positionCollateral, positionLiquidationPrice, positionOpenPrice, positionSide,
} from "veranta-sdk";

const data = await client.account.positions();  // UserData

for (const pos of data.positions) {
  console.log(positionSide(pos), positionCollateral(pos), "USDC at", positionOpenPrice(pos),
    "liquidation at", positionLiquidationPrice(pos));
}

for (const order of data.limitOrders) {
  console.log(limitOrderSide(order), limitOrderCollateral(order), "at", limitOrderPrice(order));
}
```

</CodeGroup>

The data comes from the core API and is already enriched: liquidation price, accrued rollover and unrealized funding are computed for you. Pass a trader address to read any account.

### Position fields

Python exposes human-unit properties on each position. TypeScript keeps the raw API object (numbers are strings in on-chain units) and gives you helper functions that return human units.

| Python | TypeScript | Meaning |
| --- | --- | --- |
| `pair_index`, `index` | `pairIndex`, `index` | Identify the position. Pass both to close and update methods |
| `side` | `positionSide(pos)` | `"long"` or `"short"` |
| `collateral`, `leverage`, `position_size` | `positionCollateral(pos)`, `positionLeverage(pos)`, `positionNotional(pos)` | USDC, multiplier, notional |
| `open_price`, `tp`, `sl`, `liquidation_price` | `positionOpenPrice(pos)`, `positionTp(pos)`, `positionSl(pos)`, `positionLiquidationPrice(pos)` | Prices. `0` means unset |
| `rollover_fee`, `unrealised_funding_fee` | `positionRolloverFee(pos)`, `positionUnrealisedFundingFee(pos)` | Accrued fees in USDC |
| `is_upside` | `pos.isPnl` | `True` on Upside pairs. Informational; closes route from the pair automatically |
| `opened_at` | `pos.openedAt` | Open timestamp. Pass it to a close made right after the open |
| `price_triggers` | `pos.priceTriggers` | All TP and SL triggers on the position, see below |

`data.position(pair_index, index)` in Python and `findPosition(data, pairIndex, index)` in TypeScript look up one position.

### Price triggers

Every take profit and stop loss attached to a position is listed as a trigger:

- **Global triggers** are the on-chain full-position levels, set at open or with `update_tp_sl` / `updateTpSl`. Their ids are deterministic (`global-tp-...`, `global-sl-...`) and are **not** accepted by the partial methods.
- **Partial triggers** are the off-chain [partial TP and SL](/trading/tp-sl#partial-tp-and-sl) orders. Their `entityId` works with the partial update and cancel methods.

<CodeGroup>

```python Python
for trig in pos.price_triggers:
    print(trig.kind, float(trig.price), "global" if trig.is_global else trig.entity_id)

pos.global_triggers     # only the on-chain levels
pos.partial_triggers    # only the off-chain partial orders
```

```typescript TypeScript
import { globalTriggers, partialTriggers, triggerKind, triggerPrice } from "veranta-sdk";

for (const trig of pos.priceTriggers ?? []) {
  console.log(triggerKind(trig), triggerPrice(trig), trig.isGlobal ? "global" : trig.entityId);
}

globalTriggers(pos);    // only the on-chain levels
partialTriggers(pos);   // only the off-chain partial orders
```

</CodeGroup>

## Live PnL

Combine a position with its pair and the live price for the same net PnL breakdown the app shows:

<CodeGroup>

```python Python
from veranta_sdk.compute import position_net_pnl

pair = await client.markets.pair(pos.pair_index)
price = await client.markets.price(pos.pair_index)
pnl = position_net_pnl(pos, pair, price)
print(f"net {pnl.net:+.2f} (gross {pnl.gross:+.2f}, closing fee {pnl.closing_fee:.2f})")
```

```typescript TypeScript
import { compute } from "veranta-sdk";

const pair = await client.markets.pair(pos.pairIndex);
const price = await client.markets.price(pos.pairIndex);
const pnl = compute.positionNetPnl(pos, pair, price);
console.log(`net ${pnl.net.toFixed(2)} (gross ${pnl.gross.toFixed(2)}, closing fee ${pnl.closingFee.toFixed(2)})`);
```

</CodeGroup>

See [Compute](/data/compute) for every field in the breakdown.

## Balances and raw reads

<CodeGroup>

```python Python
balance = await client.account.usdc_balance()          # human USDC
raw = await client.account.positions_onchain()         # raw on-chain read through the tx-builder
```

```typescript TypeScript
const balance = await client.account.usdcBalance();    // human USDC
const raw = await client.account.positionsOnchain();   // raw on-chain read through the tx-builder
```

</CodeGroup>

Use the on-chain read when you need the unprocessed contract state. For everything else, `positions()` is the right call.
