---
title: Delegates and API Keys
description: "Register trading keys that can never touch your funds."
---

A delegate, also called an API key, is a separate key registered to your wallet. It signs orders on your behalf while the wallet keeps the funds. This is the recommended setup for bots, agents and apps.

| | Wallet key | API key |
| --- | --- | --- |
| Trade: open, close, TP and SL, margin, TWAP | Yes | Yes |
| Withdraw funds, approve USDC | Yes | No |
| Add or remove delegates | Yes | No |
| Referrals, claims, LP vault, builder code management | Yes | No, these are caller-scoped |

The SDK enters delegate mode automatically when the signing key's address differs from the trader address you configured.

## The easy way: the API Key Generator

Generate a key on the [Veranta API Key Generator](https://delegate.veranta.xyz/). One wallet signature registers it. Set the two environment variables and trade. See the [quickstart](/quickstart).

In a React app, `useSessionKey()` does the same from the browser. See [React hooks](/frontend/react#one-click-trading-with-session-keys).

## Register a key yourself

You can register any key programmatically. Your wallet key signs one `DelegateReq` message, is used for that single signature and is never stored. Submission is gasless.

<CodeGroup>

```python Python
import time
from veranta_sdk import AsyncVeranta, LocalSigner

async with AsyncVeranta(private_key=API_KEY, trader_address=WALLET) as client:
    await client.account.register_delegate(
        delegate=LocalSigner(API_KEY).address,
        expiry_seconds=int(time.time()) + 90 * 24 * 3600,   # absolute unix time, in seconds
        trader_signer=LocalSigner(WALLET_KEY),               # one signature, not stored
    )
```

```typescript TypeScript
import { Veranta, toSigner } from "veranta-sdk";

const client = new Veranta({ privateKey: API_KEY, trader: WALLET });
await client.account.registerDelegate(
  toSigner(API_KEY).address,
  Math.floor(Date.now() / 1000) + 90 * 24 * 3600,          // absolute unix time, in seconds
  toSigner(WALLET_KEY),                                    // one signature, not stored
);
```

</CodeGroup>

<Warning>
The expiry is an **absolute** unix timestamp in seconds. It is not a duration and not milliseconds. The API rejects anything that is not a future timestamp.
</Warning>

Registration needs no RPC and no ETH: it rides the new key's own EIP-7702 smart account.

## Check and verify

<CodeGroup>

```python Python
status = await client.account.delegation_status()
# {"isEnabled": True, "expiry": ..., "canDelegatedAction": ..., "canSignIntents": ...}

await client.account.verify_delegation()   # raises DelegationError if the key cannot act
```

```typescript TypeScript
const status = await client.account.delegationStatus();
// { isEnabled: true, expiry: ..., canDelegatedAction: ..., canSignIntents: ... }

await client.account.verifyDelegation();   // throws DelegationError if the key cannot act
```

</CodeGroup>

Call the verify method when your bot starts so a revoked or expired key fails fast. It does nothing when the signer is the wallet itself.

## Revoke

<CodeGroup>

```python Python
await client.account.revoke_delegate(delegate_address)   # wallet key only
```

```typescript TypeScript
await client.account.revokeDelegate(delegateAddress);    // wallet key only
```

</CodeGroup>

Revoking kills any in-flight orders signed by that key. You can also revoke from the API Key Generator.
