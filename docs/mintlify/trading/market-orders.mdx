title: Market Orders

A market order fills at the current price. This page covers opening, closing, coin-sized orders, and how to watch an order's lifecycle.

## Open a position

<CodeGroup>

```python Python
receipt = await client.trade.market_open(
    "ETH/USD", "long",
    collateral=100,          # USDC
    leverage=10,
    take_profit=4200,        # optional, a price
    stop_loss=2900,          # optional, a price
)
```

```typescript TypeScript
const receipt = await client.trade.marketOpen("ETH/USD", "long", {
  collateral: 100,         // USDC
  leverage: 10,
  takeProfit: 4200,        // optional, a price
  stopLoss: 2900,          // optional, a price
});
```

</CodeGroup>

| Python | TypeScript | Default | Meaning |
| --- | --- | --- | --- |
| `pair` | `pair` | required | Symbol such as `"ETH/USD"` or `"BTC_UPSIDE"`, or the pair index |
| `side` | `side` | required | `"long"` or `"short"` |
| `collateral` | `collateral` | required | USDC you put in |
| `leverage` | `leverage` | required | Multiplier. `10` means 10x |
| `take_profit`, `stop_loss` | `takeProfit`, `stopLoss` | none | Trigger prices |
| `open_price` | `openPrice` | live price | The reference price the fill is checked against, plus or minus the slippage |
| `slippage_percent` | `slippagePercent` | `1` | Maximum slippage. `1` means 1% |
| `skip_validation` | `skipValidation` | `False` | Skip the API's pre-trade checks |
| `wait` | `wait` | `True` | Follow the order until it settles |
| `on_event` | `onEvent` | none | A function that sees each lifecycle event live |
| `builder_fee_percent` | `builderFeePercent` | config default | Per-order [builder fee](/builders/builder-codes) |

<Info>
**Upside markets need no flag.** Upside pairs are separate markets with an `_UPSIDE` suffix, for example `BTC_UPSIDE/USD` next to `BTC/USD`. They charge no open or close fee and take a tiered share of profit instead. Open one and the SDK sends the right order type by itself. Upside pairs are market-only: no limit orders and no TWAP. See [Markets](/data/markets#upside-markets).
</Info>

## Open a coin-sized position

Sometimes you want exactly 0.5 ETH of exposure rather than a USDC notional. `market_open_coin` / `marketOpenCoin` targets a coin amount, and the fill leverage floats between the minimum and maximum you allow.

<CodeGroup>

```python Python
await client.trade.market_open_coin(
    "ETH/USD", "long",
    collateral=100,
    coin_exposure=0.5,       # ETH
    leverage=10,             # reference leverage, required by the contract
    min_leverage=5, max_leverage=20,
)
```

```typescript TypeScript
await client.trade.marketOpenCoin("ETH/USD", "long", {
  collateral: 100,
  coinExposure: 0.5,       // ETH
  leverage: 10,            // reference leverage, required by the contract
  minLeverage: 5, maxLeverage: 20,
});
```

</CodeGroup>

`leverage` is required even though the fill leverage floats, because the contract struct demands it. The minimum and maximum default to the pair's leverage limits when you leave them out.

## Close a position

Close by collateral, partially or fully, or by coin amount. You need the pair and the position's `index`, both of which come from [positions](/account/positions).

<CodeGroup>

```python Python
pos = (await client.account.positions()).positions[0]

# full close: pass the whole collateral
await client.trade.market_close(pos.pair_index, pos.index, collateral_to_close=float(pos.collateral))

# or close 0.25 ETH worth
await client.trade.market_close_coin(pos.pair_index, pos.index, coin_exposure=0.25)
```

```typescript TypeScript
import { positionCollateral } from "veranta-sdk";

const pos = (await client.account.positions()).positions[0];

// full close: pass the whole collateral
await client.trade.marketClose(pos.pairIndex, pos.index, { collateralToClose: positionCollateral(pos) });

// or close 0.25 ETH worth
await client.trade.marketCloseCoin(pos.pairIndex, pos.index, { coinExposure: 0.25 });
```

</CodeGroup>

| Python | TypeScript | Meaning |
| --- | --- | --- |
| `trade_index` | `tradeIndex` | The position's `index` |
| `collateral_to_close` or `coin_exposure` | `collateralToClose` or `coinExposure` | How much to close. Partial amounts are fine |
| `expected_price` | `expectedPrice` | Reference price. Resolved from the live feed when omitted |
| `open_timestamp` | `openTimestamp` | Pins the close to a specific open. See the warning below |

Positions on Upside pairs close with the Upside close type automatically.

<Warning>
A close is tied to the position's open timestamp. If you open and close in quick succession and hit a `PositionMismatch` simulation failure, pass `open_timestamp=pos.opened_at` / `openTimestamp: pos.openedAt`, or fetch positions again first.
</Warning>

## Follow the order lifecycle

Market orders go through the batched-market service, which streams the lifecycle back: `MarketOrderAccepted`, then `MarketOrderInitiated` with the on-chain order id and transaction, then `MarketOrderExecuted`. In between you may see `AttemptFailed` events when an attempt hit a retryable condition. With the default `wait=True` the receipt already reflects the executed fill:

<CodeGroup>

```python Python
receipt = await client.trade.market_open("ETH/USD", "long", collateral=100, leverage=10)
print(receipt.route)         # "batched-market"
print(receipt.tx_hash)       # execution transaction
print(receipt.order_id)      # on-chain order id
print(receipt.tracking_id)   # lifecycle replay handle
```

```typescript TypeScript
const receipt = await client.trade.marketOpen("ETH/USD", "long", { collateral: 100, leverage: 10 });
console.log(receipt.route);       // "batched-market"
console.log(receipt.txHash);      // execution transaction
console.log(receipt.orderId);     // on-chain order id
console.log(receipt.trackingId);  // lifecycle replay handle
```

</CodeGroup>

A fill the protocol declines, for example because the price moved past your slippage, raises `RelayError` instead of returning a receipt. The error's `code` carries the reason: a contract error name such as `WrongSl`, or a service code such as `ATTEMPTS_EXHAUSTED`.

### Watch the events while the SDK settles

Pass `on_event` / `onEvent` to log every event as it happens while the call still waits for the outcome. The hook sees the accepted event, every retryable `AttemptFailed` with its `attempt`, `code`, `message` and `willRetry`, the initiation event, and the terminal event, even when that terminal event makes the call raise.

<CodeGroup>

```python Python
from veranta_sdk import BatchedMarketEvent

def journey(ev: BatchedMarketEvent) -> None:       # async def works too
    print("order event", ev.seq, ev.type, ev.data)

receipt = await client.trade.market_open("ETH/USD", "long", collateral=100, leverage=10, on_event=journey)
```

```typescript TypeScript
const receipt = await client.trade.marketOpen("ETH/USD", "long", {
  collateral: 100,
  leverage: 10,
  onEvent: (ev) => console.log("order event", ev.seq, ev.type, ev.data),
});
```

</CodeGroup>

Keep the hook fast; it runs inline. If it throws, the local wait stops but the order keeps executing on the server, and you can settle it later from the tracking id.

### Settle later

With `wait=False` the call returns as soon as the order is accepted. The transaction hash is still empty at that point. Settle from the tracking id whenever you like:

<CodeGroup>

```python Python
accepted = await client.trade.market_close(pos.pair_index, pos.index, collateral_to_close=50, wait=False)

outcome = await client.engine.batched_market.wait(accepted.tracking_id)
print(outcome.tx_hash)
for ev in outcome.events:            # the full persisted lifecycle
    print(ev.seq, ev.type, ev.data)
```

```typescript TypeScript
const accepted = await client.trade.marketClose(pos.pairIndex, pos.index, { collateralToClose: 50, wait: false });

const outcome = await client.engine.batchedMarket.wait(accepted.trackingId!);
console.log(outcome.txHash);
for (const ev of outcome.events) {   // the full persisted lifecycle
  console.log(ev.seq, ev.type, ev.data);
}
```

</CodeGroup>

`status(tracking_id, after_seq)` / `status(trackingId, afterSeq)` is the single non-blocking poll. Every event has a `seq`, so a process that crashed can resume without missing or double-counting events.

## The fill payload

The terminal `MarketOrderExecuted` event carries the trade exactly as it executed on-chain. It is available as `receipt.raw` with the default wait, or as `outcome.terminal.data` when you settle later.

| Field | Meaning |
| --- | --- |
| `orderId`, `transactionHash` | On-chain order id and execution transaction |
| `open` | `true` for an open, `false` for a close |
| `price` | Execution price (1e10) |
| `positionSizeUSDC` | Filled notional in USDC (1e6) |
| `percentProfit` | Realized PnL as a percent (1e10), meaningful on closes |
| `usdcSentToTrader` | USDC returned to the trader on a close (1e6) |
| `isPnl`, `coinExposure`, `isCoinExposureFixed` | Upside flag, base-asset exposure (1e10), coin-sized flag |
| `t` | The stored trade: `trader`, `pairIndex`, `index`, `initialPosToken` (final collateral, 1e6), `positionSizeUSDC`, `openPrice`, `buy`, `leverage`, `tp`, `sl`, `timestamp` |

Every number in this payload is a **string in raw on-chain units**, because several exceed float precision. Convert with `from_usdc` / `from_1e10` in Python or `fromUsdc` / `from1e10` in TypeScript.

Size increases end with `PositionSizeIncreased` instead. It has no fill `price`, `percentProfit` or `usdcSentToTrader`. It reports `coinExposureAdded` and `t` as the **blended resulting position**, with open price, leverage and collateral recomputed on-chain.
