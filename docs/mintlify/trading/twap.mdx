## TWAP

A TWAP order splits a large open or close into slices executed over a run time you choose. It is useful when a single fill would pay too much spread or exceed the available liquidity.

The SDK signs a TWAP intent and sends it to the Veranta TWAP service, which registers the order on-chain and answers right away. The receipt carries the transaction hash and the on-chain TWAP id in `order_id` / `orderId`.

TWAP is not available on Upside pairs. The SDK raises `ValidationError` with code `UPSIDE_MARKET_ONLY` before sending anything.

### Open

<CodeGroup>

```python Python
receipt = await client.trade.twap_open(
    "ETH/USD", "long",
    collateral=1000,              # spread over the run time
    run_time_seconds=600,         # 10 minutes
    leverage=10,
    max_leverage=20,              # required by the contract
)
print(receipt.tx_hash, receipt.order_id)   # order_id is the TWAP id
```

```typescript TypeScript
const receipt = await client.trade.twapOpen("ETH/USD", "long", {
  collateral: 1000,             // spread over the run time
  runTimeSeconds: 600,          // 10 minutes
  leverage: 10,
  maxLeverage: 20,              // required by the contract
});
console.log(receipt.txHash, receipt.orderId);  // orderId is the TWAP id
```

</CodeGroup>

| Python | TypeScript | Meaning |
| --- | --- | --- |
| `collateral` | `collateral` | Total USDC across all slices |
| `run_time_seconds` | `runTimeSeconds` | Must be within the pair's TWAP minimum and maximum run time |
| `leverage`, `max_leverage` | `leverage`, `maxLeverage` | Both required |
| `coin_exposure` | `coinExposure` | Optional. Targets a fixed coin amount instead |

<Warning>
Each slice must clear the pair's minimum position size, which is `min_lev_pos_usdc` / `minLevPosUSDC` in notional. Too little collateral over too long a run time fails with `BelowMinPosition`. Check the pair's TWAP params (minimum and maximum run time, frequency, fee) before sizing.
</Warning>

### Close

<CodeGroup>

```python Python
await client.trade.twap_close(pos.pair_index, pos.index, coin_exposure_to_close=0.5, run_time_seconds=300)
```

```typescript TypeScript
await client.trade.twapClose(pos.pairIndex, pos.index, { coinExposureToClose: 0.5, runTimeSeconds: 300 });
```

</CodeGroup>

### List and cancel

<CodeGroup>

```python Python
twaps = await client.account.twaps()              # paginated; include_canceled=True for history
twap = await client.account.twap(123)             # one TWAP by id; None if unknown
await client.trade.twap_cancel(twap_id=123)       # the id from receipt.order_id or twaps()
```

```typescript TypeScript
const twaps = await client.account.twaps();       // paginated; { includeCanceled: true } for history
const twap = await client.account.twap(123);      // one TWAP by id; null if unknown
await client.trade.twapCancel(123);               // the id from receipt.orderId or twaps()
```

</CodeGroup>

Cancelling signs a small intent over the TWAP id. Your wallet key or an active API key both work.

## RFQ

Request-for-quote orders fill a large order at a quoted price, within the maximum slippage you accept.

<Note>
RFQ is not live on Veranta yet. The methods exist in both SDKs so your integration is ready when it ships; calls fail until then.
</Note>

<CodeGroup>

```python Python
await client.trade.rfq_open("ETH/USD", "long", collateral=5000, leverage=5, max_leverage=10, max_slippage_percent=0.5)
await client.trade.rfq_close(pos.pair_index, pos.index, coin_exposure_to_close=1.0, max_slippage_percent=0.5)
```

```typescript TypeScript
await client.trade.rfqOpen("ETH/USD", "long", { collateral: 5000, leverage: 5, maxLeverage: 10, maxSlippagePercent: 0.5 });
await client.trade.rfqClose(pos.pairIndex, pos.index, { coinExposureToClose: 1.0, maxSlippagePercent: 0.5 });
```

</CodeGroup>

There is no trader-side RFQ cancel on-chain.
