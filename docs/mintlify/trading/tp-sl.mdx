---
title: Take Profit and Stop Loss
description: "Full-position TP and SL levels on-chain, and partial TP and SL as trigger orders."
---

Veranta has two ways to take profit or stop a loss. Pick by whether you want to close the whole position or just part of it.

| | Full position | Partial |
| --- | --- | --- |
| Method | `update_tp_sl` / `updateTpSl` | `partial_tp_sl` / `partialTpSl` |
| Closes | The entire position | A slice, sized in coin units |
| Stored | On-chain | Off-chain, with the Veranta operator |
| Change it | Set new levels | `update_partial_tp_sl` / `updatePartialTpSl` with the entity id |
| Remove it | Set the level to `0` | `cancel_partial_tp_sl` / `cancelPartialTpSl` |
| Shows up as | Global triggers on the position | Partial triggers with an `entityId` |

## Full-position TP and SL

<CodeGroup>

```python Python
pos = (await client.account.positions()).positions[0]

await client.trade.update_tp_sl(
    pos.pair_index, pos.index,
    take_profit=4200,
    stop_loss=2900,       # None keeps a level, 0 clears it
)
```

```typescript TypeScript
const pos = (await client.account.positions()).positions[0];

await client.trade.updateTpSl(pos.pairIndex, pos.index, {
  takeProfit: 4200,
  stopLoss: 2900,       // undefined keeps a level, 0 clears it
});
```

</CodeGroup>

Leaving a level out keeps it unchanged: the SDK copies the current value from the position, because the signed message always carries both legs. A stop loss of `0` removes the stop loss. A position always has a take profit on-chain, so a take profit of `0` resets it to the pair's maximum gain cap, typically +2500%, rather than removing it.

<Note>
Full-position updates are signed intents sent to the core API, which executes them through the Veranta operator. The contracts have no public entry point for them, so this path is the same in relayer and direct mode. With the default wait the SDK polls the position until the new levels are visible.
</Note>

You can also set both levels when you open. See [Market orders](/trading/market-orders).

## Partial TP and SL

A partial trigger closes a slice of the position when the price reaches your level. The SDK signs the order and stores it with the operator, who executes it on-chain when it triggers. Keep the returned record: its `entityId` is your handle for updates and cancels.

<CodeGroup>

```python Python
order = await client.trade.partial_tp_sl(
    pos.pair_index, pos.index,
    side=pos.side,              # side of the position being trimmed
    kind="take_profit",         # or "stop_loss"; "tp" and "sl" work too
    coin_exposure=0.25,         # how much to close, in coin units
    trigger="fixed",            # "fixed" uses price; "percentage" uses percentage
    price=3900,
)
```

```typescript TypeScript
import { positionSide } from "veranta-sdk";

const order = await client.trade.partialTpSl(pos.pairIndex, pos.index, {
  side: positionSide(pos),    // side of the position being trimmed
  kind: "take_profit",        // or "stop_loss"; "tp" and "sl" work too
  coinExposure: 0.25,         // how much to close, in coin units
  trigger: "fixed",           // "fixed" uses price; "percentage" uses percentage
  price: 3900,
});
```

</CodeGroup>

| Python | TypeScript | Meaning |
| --- | --- | --- |
| `trigger` | `trigger` | `"fixed"` takes a `price`. `"percentage"` takes a gain or loss `percentage` |
| `percentage` | `percentage` | Signed percent for percentage triggers |
| `open_timestamp` | `openTimestamp` | Pin the trigger to a specific open if the position was just modified |

Existing triggers are listed on each position. Partial orders carry `is_global=False` / `isGlobal: false` and an `entityId`. The full-position levels show up as global triggers with deterministic ids such as `global-tp-...`. Passing a global id to the partial update or cancel methods raises `ValidationError`; manage those levels with the full-position method instead.

## Update a partial trigger

An update replaces the stored order with a freshly signed one. Pass the **full** new order, not a diff.

<CodeGroup>

```python Python
order = await client.trade.update_partial_tp_sl(
    order["entityId"],
    pos.pair_index, pos.index,
    side=pos.side, kind="take_profit", coin_exposure=0.25,
    trigger="fixed", price=4100,          # the new level
)
```

```typescript TypeScript
const updated = await client.trade.updatePartialTpSl(order.entityId, pos.pairIndex, pos.index, {
  side: positionSide(pos), kind: "take_profit", coinExposure: 0.25,
  trigger: "fixed", price: 4100,        // the new level
});
```

</CodeGroup>

<Warning>
An update mints a **new** `entityId`. The backend deletes the old order and stores the replacement atomically. Always keep the returned record; the id you passed in is gone.
</Warning>

## Cancel a partial trigger

<CodeGroup>

```python Python
await client.trade.cancel_partial_tp_sl(order)          # the record
await client.trade.cancel_partial_tp_sl("665f1c2a...")  # or just the entityId
```

```typescript TypeScript
await client.trade.cancelPartialTpSl(order);            // the record
await client.trade.cancelPartialTpSl("665f1c2a...");    // or just the entityId
```

</CodeGroup>

The cancel signs a small `CancelOffchainOrder` message over the entity id to prove ownership. Your wallet key or an active API key both work.
