This page is generated from the server code (`pnpm docs:gen` in the veranta-mcp repository), so it always matches the published version. There are 36 tools in six toolsets: `core`, `analysis`, `alerts` and `approvals` are on by default, `lp` and `referral` are opt-in through `VERANTA_TOOLSETS`. `link_telegram` is listed only on the hosted connector, and a server without a session key lists no trade or funds tool at all. Every tool returns structured data plus a short text summary, and every error carries a `code`, a `message` and a `fix` that names the next step. For a guided walk through what the tools do together, with prompts to try, read [Features](/ai/features).

Gates: **read** never changes anything, **trade** signs orders or position changes with the session key, **funds** moves USDC between the wallet and a vault, **admin** changes server-side state such as alerts.

## Inputs

### check_setup

Call this first in every session. Reports the network, endpoints, the trader account, the signer (none, session key or KMS), whether the session key is an active delegate and when it expires, USDC balance and trading allowance, builder-fee status (rate, fee allowance and whether the session key sits on the fee-charging template), the enabled toolsets, the policy preset with what is left of today's budgets and whether trading is paused, and a list of issues with the exact fix for each. Use it again whenever a trade tool fails with a config, delegation, policy or allowance error.

No inputs.

### get_markets

Search and list Veranta markets with live price, 24h change, funding and net carry rate per side (funding plus borrow), open interest, skew, leverage range, fees and market hours. Use it to resolve a symbol before quoting, to answer 'what can I trade' or 'what is BTC doing', and to compare a few pairs. For one pair in depth (spread at a size, liquidity, candles) use get_market. Symbols look like ETH/USD, US500/USD, EUR/USD, XAU/USD; common names such as gold, nasdaq or bitcoin work in search. The 24h change of a market that was closed for more than 30 hours is marked (s) and measured since its last close. Example: \{ search: 'gold' \} or \{ symbols: ['ETH/USD', 'BTC/USD'] \} or \{ assetClass: 'fx', openOnly: true \}.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `search` | string | no | Free text matched against the symbol or a common name, for example 'eth', 'gold', 'nasdaq', 'US500' or 'nvda'. |
| `symbols` | array of string | no | Exact pairs to return, for example ['ETH/USD', 'XAU/USD']. Unknown ones are listed in 'unresolved'. |
| `assetClass` | `crypto`, `equity`, `fx`, `metal`, `commodity` | no | Only this asset class. |
| `openOnly` | boolean | no | Only markets that are open for trading right now. Default `false`. |
| `sortBy` | `openInterest`, `symbol`, `change24h`, `funding` | no | Order of the list. openInterest is total OI in USD, funding is the net carry longs pay per hour (funding plus borrow). Default `"openInterest"`. |
| `limit` | integer | no |  Default `25`. |
| `includePrices` | boolean | no | Fetch live prices and 24h change for the returned pairs. Turn off for a faster catalog-only answer. Default `true`. |

### get_market

Everything about one market before trading it: live price and 24h change (measured since the last close when the market was shut for more than 30 hours), the net carry rate per side (funding plus borrow) with its parts, open interest and skew, the spread quoted right now for a given size and side with its mechanism, how much more can be opened (headroom, including the trader's per-pair wallet cap), maker and taker fees, leverage range with any temporary cap, minimum position, market hours and next open or close, TWAP limits, notes such as the ETF a US500/US100 price tracks or a futures roll, and optionally a 24h candle summary. Use get_markets to find the symbol first if unsure. Example: \{ pair: 'XAU/USD', side: 'short', notionalUsd: 5000 \}.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `pair` | string | yes | Symbol, common name or index, for example 'ETH/USD', 'eth', 'gold', 'US500/USD'. |
| `side` | `long`, `short` | no | Side used for the spread quote and headroom. Default `"long"`. |
| `notionalUsd` | number | no | Position size in USD used to quote the spread (collateral times leverage). Default `1000`. |
| `includeCandles` | boolean | no | Add the last 24 hours of hourly candles as a summary and a candle-based 24h change. Off by default; it costs one more upstream call. Default `false`. |

### get_account

The trader's account in one call: USDC balance and allowance, every open position with entry, live price, net PnL after fees and funding (clamped the way the contract settles: gross between minus 100 percent and the pair's max gain, net never below minus collateral), health (trade value as percent of collateral), liquidation price and distance, TP and SL, standing limit orders, running TWAPs, session key expiry, exposure by asset class, and alerts: collateral 60 percent consumed (warning) or 75 percent (critical), past liquidation and awaiting the keeper, no stop loss, key expiring, market closed. Position ids look like '3:0' (pairIndex:tradeIndex) and are what set_risk and quote_trade close take; cancel_order takes orderIndex, twapId or entityId, not position ids. Use limit and sortBy ('liqDistance', 'pnl', 'notional') on large accounts; totals and alerts always cover every position. Pass trader to inspect any other wallet read-only.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `trader` | string | no | Another wallet to look at. Defaults to the configured trader. |
| `includeOrders` | boolean | no | Include standing limit orders. Default `true`. |
| `includeTwaps` | boolean | no | Include running TWAP orders. Default `true`. |
| `limit` | integer | no | Positions to list in detail. Totals, exposure and alerts always cover every position; when truncated, a per-pair aggregate is added. Default `25`. |
| `sortBy` | `liqDistance`, `pnl`, `notional` | no | Order of the positions: liqDistance puts the closest to liquidation first, pnl the largest loss first, notional the largest position first. Default is the API order. |

For open positions use get_account. Example: \{ kind: 'trades', limit: 10 \} or \{ kind: 'pnl_by_day', period: '7d' \}.

| `kind` | `summary`, `portfolio`, `trades`, `orders`, `pnl_by_day` | no | summary: realized net PnL since the V2 cutoff plus all-time v1 aggregates (win rate, fees, loss protection, volume, best closes). portfolio: the portfolio page in one call (PnL for the period, portfolio value, volume, PnL breakdown into gross, funding and fees, win rate, trade count, biggest win, most traded market, and the cumulative PnL chart). trades: fills with fees. orders: order history. pnl_by_day: daily realized PnL for a period from the v2 profit-loss history. ### quote_trade

Price a trade before executing it: opens, increases and closes as market, limit, stop_limit or twap, one leg or a basket. Returns the expected entry (mark plus live spread) or exit (mark minus spread), every fee (maker or taker open fee, estimated close fee, builder fee, carry settled by increases), liquidation price and distance, take profit and stop loss prices, expected PnL for closes, validation against the pair's rules and the wallet balance, market context and the policy verdict (allow, confirm or block). The quoteId is valid for about 30 seconds and executes exactly once through execute_trade. Give two of collateralUsd, notionalUsd and leverage. Examples: \{ pair: 'ETH/USD', side: 'long', collateralUsd: 200, leverage: 3, stopLossPercent: 10 \} or \{ action: 'close', positionId: '1:0', closeFraction: 0.5 \} or \{ legs: [...] \}.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `action` | `open`, `increase`, `close` | no | open a new position, increase an existing one, or close (part of) an existing one. Default `"open"`. |
| `pair` | string | no | Pair symbol for open, for example 'ETH/USD'. For increase or close you may pass positionId instead. |
| `positionId` | string | no | Position handle from get_account ('pairIndex:tradeIndex', for example '1:0'). Needed for increase and close unless pair plus side identifies exactly one position. |
| `side` | `long`, `short` | no | Required for open. For close, selects the position when positionId is omitted. |
| `collateralUsd` | number | no | Collateral in USD. Give two of collateralUsd, notionalUsd and leverage. |
| `notionalUsd` | number | no | Position size in USD (collateral times leverage). |
| `leverage` | number | no | Leverage multiplier. Defaults to the position's leverage for increase. |
| `orderType` | `market`, `limit`, `stop_limit`, `twap` | no | market fills now. limit waits for limitPrice (longs below market, shorts above). stop_limit triggers through limitPrice in the other direction (longs above market, shorts below). twap spreads the order over twapRunTimeSeconds and cannot carry takeProfit or stopLoss. Default `"market"`. |
| `limitPrice` | number | no | Price for limit and stop_limit orders. |
| `takeProfit` | number | no | Take profit price. Or use takeProfitPercent. Not allowed on twap legs. |
| `takeProfitPercent` | number | no | Take profit as percent gain on collateral (100 means the collateral doubles), before close fee, funding and borrow. On Upside pairs the target is net of the profit share. |
| `stopLoss` | number | no | Stop loss price. Or use stopLossPercent. Not allowed on twap legs. |
| `stopLossPercent` | number | no | Stop loss as percent of collateral lost (10 means lose about 10 percent of collateral), before close fee, funding and borrow. A stop is a trigger level: the close settles at the oracle price when the keeper transaction lands, minus spread, so the realized loss can exceed this percent. |
| `slippagePercent` | number | no | Maximum deviation from the quoted entry price (mark plus spread) accepted for market opens and increases; the web app uses 3. Ignored on close legs, which have no on-chain slippage bound. Default `1`. |
| `closeFraction` | number | no | For close: fraction of the position to close (1 closes everything). |
| `closeCollateralUsd` | number | no | For close: collateral amount to close, alternative to closeFraction. |
| `twapRunTimeSeconds` | integer | no | For twap: total run time in seconds, a whole multiple of the pair's slice frequency. |
| `legs` | array of object | no | Basket: several legs quoted together. When given, the top-level leg fields are ignored. |
| `note` | string | no | Free text kept in the journal, for example the reason for the trade. |

### execute_trade

Execute a quote from quote_trade. Runs once per quoteId (a retry returns the same result), rejects expired quotes and prices that moved more than the leg's slippagePercent since the quote (3 percent for closes), re-checks the policy and the session key, waits for the fill and returns the fill price, realized PnL for closes, order id, trackingId, transaction link and the resulting position. If a leg times out it is reported as submitted with its trackingId: call check_order, never re-quote blindly. With a builder code configured (VERANTA_BUILDER_CODE), market legs relay directly and have no trackingId or lifecycle: the leg counts as filled once get_account shows the position (new, grown or reduced), the new position's open price stands in for the fill price on opens and no fill price is reported for increases or closes; if the keeper has not acted within the timeout the leg is submitted with its transaction hash and get_account tells the outcome. If the quote's policy verdict was confirm, show the user the confirmation sentence first and pass confirmed: true only after a clear yes.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `quoteId` | string | yes | The quoteId returned by quote_trade. |
| `confirmed` | boolean | no | Set true only after the user explicitly agreed to the quote's confirmation sentence. Default `false`. |
| `stopOnFailure` | boolean | no | For baskets: stop at the first failing leg instead of continuing. Default `true`. |

### check_order

Look up a batched-market order by the trackingId execute_trade reported for a submitted (timed out) leg: the persisted lifecycle events and, once a terminal event landed, whether it filled (with price, order id and transaction), was canceled by the protocol, or failed. With wait: true it polls until settled or timeoutSeconds. Call this before quoting the same trade again. Only batched-market legs have a trackingId: market orders placed with a builder code (VERANTA_BUILDER_CODE) relay directly and cannot be tracked here; for those, get_account shows whether the position appeared or changed.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `trackingId` | string | yes | The trackingId reported by execute_trade for a submitted leg. |
| `wait` | boolean | no | Keep polling until the order settles or timeoutSeconds pass. Default `false`. |
| `timeoutSeconds` | integer | no | With wait: how long to poll. Default `30`. |

### set_risk

Change the risk settings of one open position: set or move the take profit and stop loss (by price or percent of collateral), trail the stop behind the price (trailStopPercent, a ratchet that never loosens), remove the stop loss, add or withdraw margin, or add, update and cancel partial take profit and stop loss triggers that close a fraction. Tightening (adding or moving a stop closer, take profit, adding margin) always works, even while trading is paused. Loosening (withdrawing margin, removing or widening a stop) counts as an increase under the policy: the resulting leverage must stay within the policy cap and it is blocked while paused. Stops are checked against the contract's cap (a stop may lose at most maxSlP percent of collateral, 80 percent on most pairs) and against the liquidation price; take profits above the pair's maximum gain are stored clamped by the contract and the result says so. Always confirm the current entry and liquidation price with get_account first. Example: \{ positionId: '1:0', stopLoss: 2400 \}, \{ positionId: '1:0', takeProfitPercent: 50, stopLossPercent: 20 \} or \{ positionId: '1:0', trailStopPercent: 2 \}.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `positionId` | string | yes | Position id from get_account ('pairIndex:tradeIndex'). |
| `takeProfit` | number | no | New take profit price. |
| `takeProfitPercent` | number | no | Take profit as percent gain on collateral from the entry price. |
| `stopLoss` | number | no | New stop loss price. |
| `stopLossPercent` | number | no | Stop loss as percent of collateral lost from the entry price. |
| `clearStopLoss` | boolean | no | Remove the stop loss entirely. Default `false`. |
| `trailStopPercent` | number | no | Trailing stop step: place the stop this percent of price behind the current price, only if that is tighter than the current stop (a ratchet; never loosens). Call it again as the price moves, or create a trailing_stop rule with manage_alerts to let the watch daemon do it. |
| `trailStopDistance` | number | no | Same as trailStopPercent but as an absolute price distance. |
| `addMarginUsd` | number | no | Add collateral from the wallet (lowers leverage and moves the liquidation price away). |
| `removeMarginUsd` | number | no | Withdraw collateral to the wallet (raises leverage; checked against the policy like an increase; not possible on Upside positions). |
| `partial` | object | no | Partial take profit or stop loss that closes only a fraction of the position at a price. |

### cancel_order

Cancel a standing limit or stop-limit order (pair plus orderIndex from get_account), a running TWAP (twapId), a partial take profit or stop loss trigger (entityId), or with kind 'all' every standing order at once (each cancel reported separately; scope with pair or kinds). Cancelling a limit order releases its escrowed collateral. Open positions are closed with quote_trade or close_positions, not here.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `kind` | `limit`, `twap`, `partial`, `all` | yes | limit: a standing limit or stop-limit open order. twap: a running TWAP. partial: a partial TP/SL trigger. all: every standing limit order, running TWAP and partial trigger (optionally scoped by pair and kinds). |
| `pair` | string | no | For limit: the pair of the order. For all: only orders on this pair. |
| `kinds` | array of string | no | For all: restrict to these kinds (default every kind). |
| `orderIndex` | integer | no | For limit: the order index from get_account. |
| `twapId` | integer | no | For twap: the on-chain twapId from get_account. |
| `entityId` | string | no | For partial: the stored trigger id. |

### close_positions

Close several positions at once by filter: everything, only losers, only winners, one pair, or a list of ids, fully or by fraction. Each close is quoted, the policy is applied to the whole set (large sets need the user's confirmation), then the closes execute one after another and every result is reported. Positions whose market is closed are skipped and named with the reopen time; the rest still close. For a single position prefer quote_trade with action 'close'. Example: \{ only: 'losing' \} or \{ only: 'pair', pair: 'BTC/USD', fraction: 0.5 \}.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `only` | `all`, `losing`, `winning`, `pair`, `ids` | no | all: every open position. losing or winning: by current net PnL. pair: every position on `pair`. ids: the listed positionIds. Default `"all"`. |
| `pair` | string | no | With only: 'pair', the symbol to close. |
| `side` | `long`, `short` | no | Optional side filter. |
| `ids` | array of string | no | With only: 'ids', position ids from get_account. |
| `fraction` | number | no | Fraction of each position to close. Default `1`. |
| `confirmed` | boolean | no | Set true after the user agreed to the confirmation sentence, if one was returned. Default `false`. |

### pause_trading

Kill switch. Blocks new positions, increases, margin withdrawals, stop removal and approvals until a human runs `veranta-mcp policy resume` on the machine. Closing positions, cancelling orders, adding margin and tightening stops keep working. Use it when the user asks to stop, when something looks wrong, or after repeated failures. It cannot be undone from the conversation.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `reason` | string | no | Why trading is being paused; shown in every later block. |

### trade_journal

The trader's notebook. Every open and close is recorded automatically with size, prices, PnL and the note given to quote_trade; placed and cancelled limit, stop-limit and TWAP orders are recorded as order entries without PnL. Use add_note to record the thesis before a trade, the reason for a change, or the lesson after a close (tags like 'breakout' or 'fomo' make reviews useful). list shows the notebook; review aggregates closes by pair, tag and regime and lists trades that still lack a lesson. This is separate from get_activity_log, which records what the server did.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `action` | `add_note`, `list`, `review` | no | add_note records a thesis, reason or lesson. list shows entries. review aggregates closes by pair, tag and regime and lists trades that still lack a note. Default `"list"`. |
| `positionId` | string | no | Position id ('pairIndex:tradeIndex') the note is about; also filters list. |
| `pair` | string | no | Pair the note is about when there is no position yet; also filters list and review. |
| `note` | string | no | The note text, in the user's words. |
| `tags` | array of string | no | Short labels such as 'breakout', 'fomo', 'plan-followed'. |
| `kind` | `note`, `review` | no | For add_note: a review is a post-trade lesson. Default `"note"`. |
| `since` | string | no | For list and review: 'today', '7d', '30d' or an ISO timestamp. Default 30 days. |
| `tag` | string | no | For list: only entries with this tag. |
| `limit` | integer | no |  Default `50`. |

### get_activity_log

The audit trail of what this server did on the user's behalf: quotes, executions and their results, policy blocks and pauses, risk changes, cancels and alerts. Use it to answer 'what did you do today' or to reconcile after a disconnect. For the trader's own notes and lessons use trade_journal. Keys and signatures are never recorded.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `since` | string | no | 'today', a duration like '24h' or '7d', or an ISO timestamp. Defaults to the last 24 hours. |
| `types` | array of string | no | Only these entry types. |

### get_market_hours
